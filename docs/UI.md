# Cyber Thunder UI

Audience: an IT Sailor approving changes, a watch officer watching the queue, a commander reading the
one-pager. Not a dashboard of charts. A queue of decisions with everything needed to decide.

## Stack and constraints
- React 18 + TypeScript + Vite, Mantine (core, hooks, notifications), Tabler icons, React Router.
- Built with `npm run build` into `cyberthunder/ui/dist`, served by the Python process. **Local UI assets:**
  no CDN links, no web fonts, no telemetry. Everything in the bundle.
- Uses `/auth/status`, `/auth/login`, `/auth/logout` and `/api/v1` (see [API](API.md)). Verified browser
  sessions use same-origin cookies and an in-memory CSRF value for unsafe requests; OAuth tokens never
  reach browser storage. Typed names in localStorage are used only for unverified development identity.
  Live updates come from `GET /audit/stream` (EventSource) plus polling of
  `/scans/{id}` and `/proposals/{id}` while something is running.
- Dark theme by default (deep navy), light theme available. Large touch-friendly buttons; the whole
  Decisions page is usable with keyboard only (`j/k` move, `a` approve, `d` deny, `enter` open).
- Every screen has loading, empty and error states. Errors show the API `detail` verbatim.

## Sign-in and permissions

In `oidc` or `mesh` mode, **Sign in** opens the configured organization provider; login and token
refresh need that provider to be reachable. Missing browser
configuration displays an administrator setup message; failed status checks do not fall back to a
typed identity. The header and Settings show the verified account, roles and **Sign out**. The UI
uses returned role permissions to restrict actions; the server independently checks node, target and
environment grants. A visible action can still be denied for a particular target. Workload identities
cannot approve human decisions. See [configuration and access policy](AUTHORIZATION.md).

Native loopback `dev` mode displays **Local test identity (unverified)** and accepts a typed name.
This is a rehearsal aid, not an authenticated account. Network container deployments need verified
configuration/TLS or mesh; UDS gateway SSO alone does not establish the application's browser session.

Browser sessions live in one server process and are lost on restart. Idle and absolute expiry require
sign-in again. Passive identity/status/audit polling does not keep a tab signed in. **Sign out**
invalidates the local session and the lease checked before subsequent background operations; it does
not revoke provider tokens or interrupt a target command already issued. See [session details](BROWSER_IDENTITY.md).

## Shell (every page)
- Left nav: Decisions, Mission, Findings, Assets, Scans, STIG Library, Vulnerability data, Audit, Reports, Settings. Commander view linked at the bottom.
- Header: product name; **kill switch** button (red, always visible; engaged state turns the whole header
  red with the reason and who engaged it; release needs a reason); **audit chain badge** (green
  "Chain verified · N records · <head8>" or red "TAMPERED at #seq"); **link indicator** (unknown/observed endpoint
  reachability, operator offline or explicit test mode, with local outbox count); **account chip** (verified account and roles, or an explicitly unverified development name);
  model indicator (backend/model, available or fallback).

## Pages
### Decisions (`/`)
The queue: proposals in `proposed` and `approved`, plus anything `applying`. Each **card** answers five
questions in plain words:
1. **What is wrong** — title, host (with asset-type icon and "simulated" badge), CAT badge, rule id / STIG id.
2. **Why it matters** — `explanation.risk` + `impact`; citations as chips (STIG ID, CCI, CVE, ATT&CK) that open the finding detail; "generated by <model>" or "template" footnote.
3. **What will change** — fix title, `fix.preview` in a collapsible code block, `kind` (script / config snippet / manifest / runbook).
4. **Could it break something** — risk tags: disruption level, reboot, services restarted, patch, reversible.
5. **How to undo** — `fix.rollback_plan`.
Buttons: **Approve**, **Deny** (note optional), after approval **Apply** (shows a step timeline: scope check →
before-state captured → applied → verified ✓, or failed → rolled back ↶, each with timestamp and audit seq),
**Rollback** on applied/verified. Policy chip when a proposal was auto-approved ("standing approval: <rule>, signed by <name>").
**Preview change** opens an audited static plan: the target, proposed payload, declared before-state
capture paths and commands, verification instructions, service/reboot impact and rollback. It shows
checks and unknowns without connecting to the target. Capture paths are not an exhaustive list of
files the payload could touch; this preview does not establish host readiness or lockout safety.
Approval and apply remain separate actions. A changed fix binding is refused rather than presented
as the approved change. Maintenance-window enforcement remains backlog work.
Filters: host, severity, asset type, state. Bulk select → approve/deny. Sort: severity, host, age.
Empty state: "Nothing waiting for a decision" with a button to start a scan.

### Mission (`/mission`)
The enclave pass, in order, on the workflow routes: what arrived (`GET /receive/cve`, `GET /receive/stig`),
discover a system, scan one target, explain and propose from those results, apply approved checklist items,
roll a version back, and read or write the per-target report. Each step shows the API detail on failure.

### Findings (`/findings`)
Table paginated in groups of 200: severity, scanner result, confidence, human review, machine/type, category/source, rule/title,
benchmark/release, observation time and fix/explanation/proposal availability. Searchable multi-select filters,
quick views and explicit ascending/descending sorts run before pagination; preferences survive refresh.
See [FINDINGS](FINDINGS.md) for category definitions and missing metadata behavior.
Click the whole row or use Enter/Space → **drawer**; nested buttons/links retain their own actions. Details include description, check text, evidence, fix text, citations
with links (public.cyber.mil search for STIG ids, nvd.nist.gov for CVEs, attack.mitre.org for techniques — links
are plain anchors; offline they simply do not resolve), explanation panel (with Regenerate), fix entry panel,
"Propose fix" button, proposal history.
Confidence shows its deterministic reason and recorded or missing provenance. Human review shows the
decision, evidence, expiry and full history; a new decision requires a reason, and a suppression also
requires a future expiry. A stale edit must reload the latest review. Verified-mode reviews require
a human principal with review permission and target access; development names remain unverified.
Active suppression blocks Propose/Apply; rollback keeps its existing guards. Raw scanner
results and overall counts remain visible when filtering by review or confidence.

### Assets (`/assets`)
Inventory table: name, type, transport, address, in scope (toggle; asks for a reason; audited), simulated badge,
last scan, open findings by CAT. Add/edit modal with per-type fields. "Discover" action shows AssetFacts.
"Load simulated range" button when the inventory is empty.
Deployment-host setup distinguishes native/runtime-local collection from an explicit SSH/WinRM host
connection. Registration requires reviewed scope; testing connectivity is a separate action. The range editor
previews IPs/CIDRs/ranges/exclusions and requires acknowledgment of normalization before saving. See [HOST_SCOPE](HOST_SCOPE.md).

### Scans (`/scans`)
Start scan (targets multi-select, modules check/hunt/cve). Run list with progress bars and per-target status and
errors. The ingest panel links STIG uploads and versions to the **STIG Library**. Drop a bulletin (IAVM JSON)
→ affected hosts and new findings. Local content preflight and per-run coverage expose missing, unconfigured
and stale scanner/content information without contacting a target or downloading. See [SCAN_CONTENT](SCAN_CONTENT.md).

### STIG Library (`/content`)

One page for uploads, downloads, catalog versions and sync times, with searchable, paginated tables:

- **Downloaded**: local files with product/type/version and provenance; rule catalogs from earlier imports
  and bundled reference XMLs. Bundled references are labelled separately and do not represent synchronized or
  installed downloads. Open a product in Browse all to compare local and listed releases and dates.
- **Maintained**: defaults to matching in-scope inventory, not all STIGs. Manual mode offers persistent
  product checkboxes, including products with no inventory target; type checkboxes select manual STIG, SRG and
  SCAP benchmark. **Select displayed / Clear displayed** affect only the visible page. **Use inventory
  recommendations** copies recommendations into a manual list. **Save selections** persists the draft;
  concurrent edits require loading the latest revision. Empty products/types do not mean everything is current.
- **Updates**: separate file checkboxes and **Download selected** for saved maintenance choices. Optional pacing
  is available only in explicit test mode; downloads open the transfer view.
- **Browse all**: searchable recognized products in the saved catalog, including products outside inventory,
  with type/selection/update filters and product-version details. This is not every raw publication format.
- **Import / transfer**: per-file progress, the latest 20 download jobs, deltas and **Rescan changed rules**. Upload XML/ZIP files from the
  browser computer offline, up to 32 MiB each, sequentially with individual errors and refresh after success.
  **Download manifest** and **Import folder** support the disconnected round trip; the folder must exist on
  the server. Unrecognized raw XML without a lock-file entry uses the 32 MiB upload validation path and shows
  **Uploaded locally** metadata; known/lock-file content retains folder-import provenance. Folder imports require
  a named actor and check the kill switch before starting and between files. Quarantine, per-file refusals and
  catalog-read errors remain visible. See [CONTENT](CONTENT.md).

Save or discard selection edits before a live check, download or manifest export. Opening the page,
**Refresh local view**, selecting checkboxes and saving never download files. The reconnect switches
`check_on_reconnect` and `auto_pull` affect reconnect only; auto-pull checks first. The server-configured periodic
check interval is displayed separately and periodic checks never auto-download.

The header distinguishes cached **Last live index** from **Snapshot index**, index save time, last successful
live check, last download and last local import; pull-created deltas do not advance the local-import time.
Local event times include full date/time and timezone offset;
publisher dates remain distinct. Failed checks do not replace the last successful check. **Matches index**
is relative to that cached index, not a claim of live freshness or executable scan coverage. Guidance catalogs
and rule counts do not establish that a scanner can execute every rule.
Unverified local uploads remain visible but do not suppress official updates when product/version metadata matches.

Browser check reported 5 Nov 2026: a Windows 11 manual STIG uploaded offline and saved selections persisted.
This validates the library workflow, not Windows scan coverage.

### Audit (`/audit`)
Live timeline (newest first, auto-follow toggle). Each row: seq, time, actor, action, outcome, subject; expand for
details JSON and hashes. Filters by action/actor/subject. "Verify chain" button shows the verifier output.
Download audit.jsonl. Audit access requires the node's `audit` permission in verified mode; target
read rights do not imply access to the node-wide audit trail.

### Reports (`/reports`)
Report history searches saved commander reports, POA&Ms, checklists and target reports by contents,
asset name/ID, scan ID and operator. Filters narrow by report type and inclusive UTC date range; results
are newest first with pagination. Open a saved report to preview its original contents or download the
original HTML, Markdown, CSV, CKLB or JSON. Historical previews do not regenerate from live findings.
Global report history/exports require node export permission and read access across current inventory;
filters do not reduce these checks. Per-target read/export rights alone do not unlock global history.
Node-wide read views separately require node `read.all`; scoped lists filter inaccessible resources.

The **Current report** selector opens the commander one-pager, Check & fix coverage, Path to fleet or
Friction log, with HTML/Markdown downloads. Coverage distinguishes native checks, benchmark totals,
structural SCAP eligibility, executable fixes, runbooks and unmapped rules; it is not a compliance score.
POA&M CSV and an updated checklist (CKLB) per host are available below. Commander, POA&M and checklist
renders save snapshots; Mission's per-target reports retain every revision. Coverage, fleet and friction
exports are not included in report history.
Existing target reports and report exports still in the pending/synced outbox are imported once.
Report history lives in `<state>/reports/history/` as portable files for both state backends. Earlier
reports that were never retained cannot be recovered from the audit log alone.

The **detection score** card compares seeded issues with findings when the range answer key is present.
"Queue for sync" puts a report in the outbox; the outbox list includes a sync button.

### Settings (`/settings`)

**Open STIG Library** links to `/content` for subscriptions, updates and imports.
Verified account and roles, with Sign out; the editable actor name appears only in local development mode.
Model status and backend. Standing approval policy editor: enabling is refused in verified mode pending
verifiable policy signing. In development, enable requires signer (= actor) and reason; rules with asset
types, max disruption, allow reboot / patch / service restart, allowlists, time window;
"Evaluate against current queue" preview. Link observations, operator-offline control, explicitly enabled test
emulation and bounded opt-in probes ([LINK](LINK.md)). Development-only demo controls: load simulated range, reset, "force
verification failure on next apply" toggle (clearly labelled as a demonstration control).

### Commander view (`/commander`)
Read-only, large type: open CAT I/II/III counts, intrusion indicators found, changes verified today, pending
decisions, audit head hash, link state. Refreshes every 10 s.

## Visual language
- Severity: CAT I red, CAT II amber, CAT III blue, info grey. Status: open / verified / rolled back / denied.
- Monospace for rule ids, hashes and payloads. Hashes always truncated to 8 with full value on hover/copy.
- Nothing animates except progress. No modals for information, only for confirmations (kill switch, deny with
  note, policy enable, scope change).

## Project layout
```
cyberthunder/ui/
  package.json  vite.config.ts  tsconfig.json  index.html
  src/main.tsx  src/App.tsx  src/api/client.ts (typed fetch, session CSRF, dev actor, SSE)  src/api/types.ts
  src/api/identity.ts  src/state/Identity.tsx (sign-in boundary and permission state)
  src/pages/{Decisions,Mission,Findings,Assets,Scans,Content,Audit,Reports,Settings,Commander}.tsx
  src/components/{Shell,KillSwitch,ChainBadge,LinkBadge,ActorChip,ProposalCard,FindingDrawer,SeverityBadge,ApplyTimeline,...}.tsx
  dist/   built output, committed (regenerate with `npm run build`; never hand-edit)
```
`vite.config.ts` proxies `/api` to `http://127.0.0.1:8000` in dev. `npm run build` must produce relative asset
paths (`base: './'`) so the app works when served from `/`.
The default Vite proxy is for local development; test verified browser login through the application's
configured HTTPS origin, including its root `/auth` routes.
